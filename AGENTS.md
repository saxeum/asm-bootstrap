# asm-bootstrap — agent instructions

Repo-specific rules for `saxeum/asm-bootstrap`. Universal rules live in the global
`~/.pi/agent/AGENTS.md` and are not repeated here.

## Where this is

Past the bootstrap. `asm1` (5 781 bytes, built by `seed/asm1` from `src/asm1.s`) is self-hosting and
**demonstrably better than the thing that built it**: 18/18 hand-emitted fixtures, 17 capability
pairs of syntax `asm0a` cannot parse, 3 superiority cases where `asm0a` fails or answers wrongly, and
11 rejections that name their line. `asm0a` is frozen history — it can no longer build the assembler,
and it has a known wrong-answer defect (`and` assembled as `add`) that `asm1` must never reproduce.

Milestones: `milestone-fixpoint` (`X == X' == X''`) and `milestone-handover` (better than `asm0a`,
and `asm0a` can no longer build it). `docs/ROADMAP.md` is where it goes next.

## Invariants

| # | invariant | how it is checked |
|---|---|---|
| 1 | **`asm0a` is frozen, and it is not a correctness reference.** 3 745 bytes of hand-written machine code: never patched, rebuilt, regenerated or "fixed". It was useful as an *independent* implementation while it could still parse the source; it can no longer parse it, and it has known wrong-answer defects (below). Treat it as history, never as truth. | sha256 in `docs/SHAS`; `make bootstrap-check` reports NOT APPLICABLE |
| 2 | **`asm1` is always built by the previous stage, never by itself.** The builder is `seed/asm1`, the promoted previous generation. Building with the binary you are replacing is how a miscompilation is preserved with nothing to compare against. | `make` uses `seed/asm1`; `make fixpoint` requires `asm1(asm1.s) == asm1` |
| 3 | **`seed/asm1` is replaced only by `make promote`**, a deliberate act with a diff to read. No build step promotes. | `make promote` is manual; `docs/toolchain.tsv` records each link |
| 4 | **Two independent implementations must agree where that is still possible.** It no longer is: `asm0a` cannot parse a 133-label source. Agreement between different implementations is evidence *about* them, not proof that either is right — see the `and` defect below. | `make bootstrap-check` (NOT APPLICABLE, said out loud) |
| 5 | **Every artifact is attributable to the assembler sha256 that built it.** "asm1" identifies nothing after the next rebuild. | `docs/provenance.tsv`; `make which FILE=…` |
| 6 | **Recording is separate from testing.** `make test` never writes the ledger; only `make record` does. A build step that absorbed drift silently is how a stale record goes unnoticed. | `make record` is the sole writer |
| 7 | **`ref/` is hand-emitted before the tool that reproduces it**, and is never regenerated by that tool. An oracle produced by its subject proves nothing. | corpus compares bytes; `ref/README.md` |
| 8 | **Exit status is never evidence.** Every test compares bytes with `cmp`. | every rule in the `Makefile` |
| 9 | **A positive test suite cannot detect truncation.** Invalid input must be *rejected with no output bytes* — a partial file is worse than none. `tests/reject/` is that suite. | `make test-reject` |
| 10 | **No tool outside the rules in the creation OR diagnosis path**: no compiler, no system assembler, no **disassembler**, no interpreter, no scripting language, no debugger. It replaced "by inspection", which failed twice (the branch gate, and `docs/oracles.md` prescribing it). `as` and `ld` are matched by inspection, not by the grep: two letters that appear in shell code |
| 11 | **`asm1` must be demonstrably better than `asm0a`, not merely different.** Every capability pair and superiority case must be able to fail, and must fail loudly if its premise stops holding (`asm0a` starts accepting the syntax, or agrees when it should not). | `make test-capability`, `make test-superior` |

## Conventions that each came from a real defect

**Writing `src/asm1.s`** (the dialect's actual limits, all discovered the hard way):

- label names ≤ 7 characters; ≤ 128 labels; no duplicate labels (they assemble, and the first
  definition wins, so a duplicate hides dead code).
- no `add r32,imm32`, no `sub r8,imm8`, no negative immediates, no hex literals, no `[base-disp]`,
  no `[rbp]` at displacement 0 (the encoder emits RIP-relative; see `docs/encodings.md`).
- `cmp r8,imm8` is **signed**: −128..127. Compare anything ≥ 128 at 32 bits.
- anything needed after `call emital` must live in memory or in `rbx`/`rbp`: `syscall` destroys
  `rcx`, `rax` and `rdx`.
- `asm1` has three passes: 0 counts, 1 validates (resolves labels and range-checks with output
  suppressed), 2 emits. Anything checked in pass 1 is checked before a single byte is written;
  anything that must fail with no output belongs there.
- buffers go **below** `rsp`. Above `rsp` is the top of the address space and the end of the stack
  mapping — 12 KB at most, ASLR-dependent.

**Editing it:**

- append self-contained blocks and anchor on content. Line-number `sed` ranges landed off by one
  three separate times and left orphaned code that still assembled; the exit status cannot see that.
- after any structural edit: check label lengths, duplicates, and that the corpus is still 18/18.

**Records:**

- `.gitignore` patterns are anchored (`/asm1`) — bare `asm1` would silently ignore `seed/asm1`.
- verification commands live in fenced blocks and are run **from the page, in a fresh directory**,
  not from shell history.

## When a build fails, triage before editing

A self-hosting build has an inherent ambiguity: the same binary is both the tool and the subject, so
a failure could be **your source edit** or **the seed you are building with**. Do not guess and do not
start bisecting the source.

```bash
make triage
```

asks the two questions that settle it, both answered from the last commit — a state that passed every
gate at the time it was made:

1. **Can the committed seed build the committed source?** No ⇒ the seed is at fault, the last promote
   was bad, and every earlier generation is recoverable with
   `git show <rev>:seed/asm1`. Yes ⇒ the seed is sound and the difference is yours.
2. **Can `asm0a` build the current source, and does it agree with the seed?** This is the only check
   that is not self-referential. It works only while `src/asm1.s` stays inside `asm0a`'s dialect —
   which is the practical reason to keep new syntax out of `asm1.s` until Phase 2 of the roadmap
   forces the handover.

A seed that reproduces itself proves only that it is stable, not that it is correct: a buggy stage can
be perfectly self-reproducing. The independent builder is the only real arbiter.

## The ambiguity is historical, and its answer is structural

`make triage` says which artefact is *inconsistent with the recorded past*. It cannot say which is
*correct*, and no tool can. The PDP-8 world did not solve that either; they arranged not to need it,
in four ways that this repo mirrors (`docs/pdp8-to-gcc.md` has the sources):

1. **The assembler was never built by itself** — PAL-III came from PAL-II on a different machine, and
   PAL-X (PDP-10) and AECL PAL8 (CDC 6600) are cross-assemblers. That is `asm0a`'s role, and the
   modern name is diverse double-compiling.
2. **The medium verified itself** — PDP-8 object tapes carry per-block checksums that the loader
   checks. That is `docs/SHAS` and every `cmp` in the Makefile.
3. **The listing was the record** — a printed listing beside the source, compared by hand. That is
   `docs/branches.tsv` and the pinned decodes.
4. **The frozen original stayed in the archive** — `asm0a` is frozen and `docs/toolchain.tsv` records
   which generation produced which binary.

What none of it catches is a deliberately miscompiling tool (Thompson, 1984). When `src/asm1.s`
outgrows `asm0a`, only 2–4 remain, which is exactly DEC's position.

## The branch pins are checked by our own decoder — and the rest of the mix is not

`tools/check-branches.sh` used to decode `asm0a` with a binutils `objdump`, so `make check` depended
on a disassembler to verify this project's output — the tool the project exists to replace. It was
suspended rather than left green, and that suspension is now over because the replacement exists:
**`src/dis.s`, a branch decoder written in the dialect and assembled by `asm1`** (`make dis`).

The gate, from a clean tree:

```
make check
```

ends with the line `branch pins: 290/290 decoded by src/dis.s -- asm0a sha 6271c5ee79034ffd, dis sha
8c9bd9b356874875`, and

```
./dis 0x142 < asm0a
```

prints `0x142 0x373 jmp`.

The gate compares every pin with `cmp`, not with a status, and it refuses to be quietly green three
ways: no decoder, no subject, or a table shorter than the 290 recorded sites; a deliberate mismatch
it must report; and any pin whose line does not match byte for byte. It prints the sha of the subject
and of the decoder in the same line as the result, because a count with no subject is not evidence.

What the decoder does, and it is deliberately no more than the gate consumes: `EB`, `E9`, `E8`,
`70`–`7F`, `0F 80`–`0F 8F`; mnemonic, `site + length + disp`, printed as unpadded lowercase hex. It
**refuses** — exit 1, nothing on stdout, and one reason word on stderr — in six named cases:
`offset` (no argument, or not a hex offset), `input` (unreadable, or larger than the buffer), `site`
(not a byte offset inside the input), `form` (not one of the forms above), `trunc` (the instruction
would run past the end of the input), `target` (the computed target is not a byte in the input).
Refusing beats guessing: a decoder that reads past its input has the same defect as an assembler that
emits a prefix, and a refusal that names the wrong rule is evidence about the wrong subject.

Its cases are in `tests/dis/cases.tsv` (`make test-dis`), expectations written by hand from the
encodings, positive and negative in one file. A decoder tested against its own output proves nothing.

The rule behind all of this is now executable: `make test-tools` greps every recipe line of the
`Makefile` and every non-comment line of `tools/*.sh` for a list of forbidden tool names, fails on a
match, and fails if its own check stops catching one. It is a tripwire, not a proof — `as` and `ld`
are two letters that appear inside shell code, so they stay under inspection — but invariant 10's
check used to be "by inspection", and inspection is what let `objdump` stay in the gate for weeks
and put it in `docs/oracles.md` as a step for the next session. Docs are deliberately not scanned:
they have to be able to say that a tool was used and is now forbidden. That sentence is the record;
an invocation is the defect.

Two things this does **not** establish, and neither may be claimed as verified:

1. **A shared bug could hide.** Our decoder checking our encoder is weaker than an independent one.
   The mitigations already exist and are not new: hand-emitted `ref/` binaries, hand-written decode
   cases, and the capability pairs that pin encodings against hand-computed dumps.
2. **The instruction-mix table in `docs/ROADMAP.md` is still provisional**, and for a narrower
   reason than before. The decoder handles branch forms only, so it confirms the branch half of that
   inventory (290 sites, `make check`) and says nothing about `mov`, `add`, `inc`. Re-deriving the
   whole mix needs a decoder for every form `asm0a` uses, which is a different and much larger tool.
   It stays labelled provisional until that exists.

The lesson from the suspension, kept because it was earned twice in one hour: writing the rule down is
not obeying it. The test is whether the forbidden tool is still in the loop.

## Known defects in `asm0a` — never imitate, never "fix" `asm1` to match

`asm0a` is frozen, so these stay. Each is a wrong answer or a silent truncation, and the reason it is
written down is that the tempting move on discovering one is to make `asm1` agree with it.

| `asm0a` | `asm1` | how `asm1` is held to it |
|---|---|---|
| **`and eax, ecx` emits `01 c8` — `add`.** It picks the mnemonic from the first letter and never re-checks the rest. | `21 c8` | `make test-superior`: fails if the two ever agree |
| entry point hardcoded to the first body byte | `entry <expr>` directive, `e_entry` written | `make test-superior` (data-before-code, must run) |
| reads at most 65 536 bytes, no check | 200 000, in 120-byte chunks, **refuses** above | `make test-superior` (99 KB source, must run) |
| 128 labels | 256 | it cannot build the source at all — the handover |
| decimal immediates only | hex, character, negative literals | `make test-capability` |
| no expressions | `label`, `label+4`, `end - start` | `make test-capability` |
| no `and` / `or` / `test`, no register forms of them | all present, immediate and register | `make test-capability` |
| fails in silence | `line N: rejected` on stderr | `make test-reject-msg` |

**The one that matters most is the first.** It was found by a capability test refusing its own pair —
`asm0a` accepted syntax it should have rejected — and it is the standing counterexample to the idea
that an independent implementation is a correct one. Agreement between two implementations is
evidence about *them*; it becomes evidence about *the truth* only when neither is known to be wrong.

## The handover has happened

`src/asm1.s` needs more labels than `asm0a`'s frozen limit allows, so **`asm0a` can no longer build
the assembler** and `make bootstrap-check` reports NOT APPLICABLE. That is by design, and it removes
the independent cross-check from this point on.

What holds the toolchain up instead, in order of strength:

1. `ref/` — hand-emitted binaries, written before the tool that reproduces them existed.
2. `tests/reject` + `tests/capability` + `tests/superior` — refusals, new-syntax equivalence, and
   inputs `asm0a` cannot handle, each with its own oracle.
3. `make fixpoint` — the new stage reproduces itself.
4. `seed/asm1` + `docs/toolchain.tsv` — the chain of promotions, every earlier generation recoverable
   with `git show <rev>:seed/asm1`.

A raising of a limit that a *builder* has to honour needs a bootstrap step: raise the limit, promote
that intermediate, and only then write source exceeding the old limit. Reversed, nothing can build
the result.
