# asm-bootstrap — agent instructions

Repo-specific rules for `saxeum/asm-bootstrap`. Universal rules live in the global
`~/.pi/agent/AGENTS.md` and are not repeated here.

## Invariants

| # | invariant | how it is checked |
|---|---|---|
| 1 | **`asm0a` is frozen.** 3 745 bytes of hand-written machine code. It is never patched, rebuilt, regenerated or "fixed", not even for a typo — every artifact's chain of custody runs through those exact bytes. | sha256 pinned in `docs/SHAS`; `sha256sum -c docs/SHAS` |
| 2 | **`asm1` is always built by the previous stage, never by itself.** The builder is `seed/asm1`, the promoted previous generation. Building with the binary you are replacing is how a miscompilation is preserved with nothing to compare against. | `make` uses `seed/asm1`; `make fixpoint` requires `asm1(asm1.s) == asm1` |
| 3 | **`seed/asm1` is replaced only by `make promote`**, a deliberate act with a diff to read. No build step promotes. | `make promote` is manual; `docs/toolchain.tsv` records each link |
| 4 | **`asm0a` and `seed/asm1` are independent implementations and must agree** on `src/asm1.s` while `asm0a` can still parse it. When the dialect outgrows `asm0a`, the check reports **NOT APPLICABLE** — never a silent pass. | `make bootstrap-check` |
| 5 | **Every artifact is attributable to the assembler sha256 that built it.** "asm1" identifies nothing after the next rebuild. | `docs/provenance.tsv`; `make which FILE=…` |
| 6 | **Recording is separate from testing.** `make test` never writes the ledger; only `make record` does. A build step that absorbed drift silently is how a stale record goes unnoticed. | `make record` is the sole writer |
| 7 | **`ref/` is hand-emitted before the tool that reproduces it**, and is never regenerated by that tool. An oracle produced by its subject proves nothing. | corpus compares bytes; `ref/README.md` |
| 8 | **Exit status is never evidence.** Every test compares bytes with `cmp`. | every rule in the `Makefile` |
| 9 | **A positive test suite cannot detect truncation.** Invalid input must be *rejected with no output bytes* — a partial file is worse than none. `tests/reject/` is that suite. | `make test-reject` |
| 10 | **No tool outside the rules in the creation or diagnosis path**: no compiler, no system assembler, no interpreter, no scripting language, no debugger. Not for a build, not for a diagnosis, not "just this once". | by inspection; when I broke this it is recorded in `docs/WAVES.md` rather than quietly dropped |

## Conventions that each came from a real defect

**Writing `src/asm1.s`** (the dialect's actual limits, all discovered the hard way):

- label names ≤ 7 characters; ≤ 128 labels; no duplicate labels (they assemble, and the first
  definition wins, so a duplicate hides dead code).
- no `add r32,imm32`, no `sub r8,imm8`, no negative immediates, no hex literals, no `[base-disp]`,
  no `[rbp]` at displacement 0 (the encoder emits RIP-relative; see `docs/encodings.md`).
- `cmp r8,imm8` is **signed**: −128..127. Compare anything ≥ 128 at 32 bits.
- anything needed after `call emital` must live in memory or in `rbx`/`rbp`: `syscall` destroys
  `rcx`, `rax` and `rdx`.
- `asm1` has three passes: 0 counts, 1 validates (resolves labels and range-checks with output
  suppressed), 2 emits. Anything checked in pass 1 is checked before a single byte is written;
  anything that must fail with no output belongs there.
- buffers go **below** `rsp`. Above `rsp` is the top of the address space and the end of the stack
  mapping — 12 KB at most, ASLR-dependent.

**Editing it:**

- append self-contained blocks and anchor on content. Line-number `sed` ranges landed off by one
  three separate times and left orphaned code that still assembled; the exit status cannot see that.
- after any structural edit: check label lengths, duplicates, and that the corpus is still 18/18.

**Records:**

- `.gitignore` patterns are anchored (`/asm1`) — bare `asm1` would silently ignore `seed/asm1`.
- verification commands live in fenced blocks and are run **from the page, in a fresh directory**,
  not from shell history.

## When a build fails, triage before editing

A self-hosting build has an inherent ambiguity: the same binary is both the tool and the subject, so
a failure could be **your source edit** or **the seed you are building with**. Do not guess and do not
start bisecting the source.

```bash
make triage
```

asks the two questions that settle it, both answered from the last commit — a state that passed every
gate at the time it was made:

1. **Can the committed seed build the committed source?** No ⇒ the seed is at fault, the last promote
   was bad, and every earlier generation is recoverable with
   `git show <rev>:seed/asm1`. Yes ⇒ the seed is sound and the difference is yours.
2. **Can `asm0a` build the current source, and does it agree with the seed?** This is the only check
   that is not self-referential. It works only while `src/asm1.s` stays inside `asm0a`'s dialect —
   which is the practical reason to keep new syntax out of `asm1.s` until Phase 2 of the roadmap
   forces the handover.

A seed that reproduces itself proves only that it is stable, not that it is correct: a buggy stage can
be perfectly self-reproducing. The independent builder is the only real arbiter.

## The ambiguity is historical, and its answer is structural

`make triage` says which artefact is *inconsistent with the recorded past*. It cannot say which is
*correct*, and no tool can. The PDP-8 world did not solve that either; they arranged not to need it,
in four ways that this repo mirrors (`docs/pdp8-to-gcc.md` has the sources):

1. **The assembler was never built by itself** — PAL-III came from PAL-II on a different machine, and
   PAL-X (PDP-10) and AECL PAL8 (CDC 6600) are cross-assemblers. That is `asm0a`'s role, and the
   modern name is diverse double-compiling.
2. **The medium verified itself** — PDP-8 object tapes carry per-block checksums that the loader
   checks. That is `docs/SHAS` and every `cmp` in the Makefile.
3. **The listing was the record** — a printed listing beside the source, compared by hand. That is
   `docs/branches.tsv` and the pinned decodes.
4. **The frozen original stayed in the archive** — `asm0a` is frozen and `docs/toolchain.tsv` records
   which generation produced which binary.

What none of it catches is a deliberately miscompiling tool (Thompson, 1984). When `src/asm1.s`
outgrows `asm0a`, only 2–4 remain, which is exactly DEC's position.

## The handover has happened

`src/asm1.s` needs more labels than `asm0a`'s frozen limit allows, so **`asm0a` can no longer build
the assembler** and `make bootstrap-check` reports NOT APPLICABLE. That is by design, and it removes
the independent cross-check from this point on.

What holds the toolchain up instead, in order of strength:

1. `ref/` — hand-emitted binaries, written before the tool that reproduces them existed.
2. `tests/reject` + `tests/capability` + `tests/superior` — refusals, new-syntax equivalence, and
   inputs `asm0a` cannot handle, each with its own oracle.
3. `make fixpoint` — the new stage reproduces itself.
4. `seed/asm1` + `docs/toolchain.tsv` — the chain of promotions, every earlier generation recoverable
   with `git show <rev>:seed/asm1`.

A raising of a limit that a *builder* has to honour needs a bootstrap step: raise the limit, promote
that intermediate, and only then write source exceeding the old limit. Reversed, nothing can build
the result.
