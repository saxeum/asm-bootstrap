# The compiler: `helloworld.c` to a running binary, and the gates it forces

This is the plan for the second half of the project: a **compiler** whose target is this dialect. It
starts with the smallest complete example, because compiling `helloworld.c` end to end already says
what every gate has to be.

## One command, and the mistake it prevents

```
make hello
```

prints `Hello, World!`. That is a two-stage pipeline underneath, and the second stage is easy to
forget:

```
./cc < helloworld.c > hello.s     the compiler writes dialect TEXT
./asm1 < hello.s > hello          the assembler is what makes a program
```

Forgetting it means running a text file full of assembly as a shell script, which answers with
`command not found` once per line and no hint about why. So the emitted text begins with:

```
; generated by cc: dialect source, not a program. Assemble it with asm1
```

A leading `;` is a comment to the assembler and a **syntax error to the shell**, so the mistake now
fails on line 1 and quotes the sentence that explains it. That line is part of the golden text, so it
is pinned like everything else the compiler emits.

## The design decision

**The compiler emits dialect source, not machine code.** Three consequences, and they are the
reason:

1. **The output is reviewable.** A compiler that emits text can be diffed, read and argued about; one
   that patches an ELF cannot. Every mistake in the backend is a visible line of assembly.
2. **`asm1` stays the only byte-producer.** Encoding correctness is already gated by 18 fixtures, 12
   rejections, 30 capability pairs, 88 coverage forms, 5 superiority cases and the fixpoint. A
   compiler emitting bytes directly would need all of that again, for itself.
3. **The gates are cheap.** `cmp` against a golden text file; `cmp` against the machine's output.

## The subset, exactly (stage 0)

```
program  := decl
decl     := 'int' 'main' '(' 'void' ')' block
block    := '{' stmt* '}'
stmt     := 'write' '(' string ')' ';'
          | 'return' number ';'          (last statement only, optional)
string   := '"' any-bytes-except-quote '"'
number   := decimal 0..255
comment  := '/*' ... '*/'  |  '//' ... end-of-line
```

Semantics, which is the whole ABI at this size:

| source | meaning |
|---|---|
| `write("s")` | `syscall` 1, fd 1, the address of a `db` holding the literal's bytes, length = `end-start` |
| `return N` | `syscall` 60 with status N |
| nothing after `}` | required; trailing tokens are refused |
| no `return` | exit 0 |
| up to 9 `write`s | one label pair per literal, `m1`/`m1end` … |

`write` is a **statement, not a call**, and that is the honest part of stage 0: there is no calling
convention yet, so a function call cannot be compiled. Turning `write(...)` into a call is gate 5
below.

## The output text, which is a designed artefact

The emitted text has one shape, and `tests/golden/hello.s` is its specification:

```
; generated by cc: dialect source, not a program. Assemble it with asm1
main:
mov eax, 1
mov edi, 1
mov esi, 4194424+m1
mov edx, m1end-m1
syscall
mov eax, 60
mov edi, 0
syscall
m1:
db "Hello, World!\n"
m1end:
```

Four things are chosen deliberately:

- **The first line is a comment** that says what the file is, because a pipeline with two stages
  invites running the first stage's output. A leading `;` is a shell syntax error, which is the
  loudest thing that can happen to a text file that is not a program.
- **`4194424+m1`** is `0x400078 + label`, the first body byte plus the label's offset: the dialect
  knows a label's value as an offset, and the image is loaded at a fixed address.
- **`m1end-m1`** is the string length as a label difference, so the compiler never counts bytes.
  This is what the expression support was built for, and it is why `label-label` had to lex without
  spaces (see the defect below).
- **All code, then all data.** A `db` between two `syscall`s would be *executed* when the write
  returns. So literals are collected during the parse and emitted after the exit block.

## The gates

```
make test-cc
```

| # | gate | fails when |
|---|---|---|
| 1 | `cc < helloworld.c` is byte-identical to `tests/golden/hello.s` | the emitted text changes shape |
| 2 | `asm1 < tests/golden/hello.s` produces a binary | the golden is not assemblable |
| 3 | that binary writes exactly `Hello, World!\n` and exits 0 | the semantics are wrong |
| 4 | a second program (two writes, `return 255`) matches its own golden and runs | only one case ever works |
| 5 | a compiled `while` loop matches its golden **and** the output of a hand-written dialect program | the compiler emits plausible wrong code, or the loop is wrong |
| 6 | ten inputs outside the subset are refused, with no output | the front end guesses |

Gate 3 is what makes gate 1 mean anything. The golden cannot be an *oracle* for its own text — it is
a regression pin, and its validity rests on the machine judging the binary it assembles to. That is
the same split as `ref/`: bytes are pinned by a hand-written expectation, meaning is pinned by
execution.

Gates 1 and 3 were both checked by breaking them: a one-byte change to the golden fails gate 1 with a
diff, and changing the string to `Hello, World?` fails gate 1 *and* gate 3 (`the binary exited 0 and
wrote [Hello, World?]`).

## What writing the oracle found in the assembler

The C file and its hand-written golden were written before the compiler, and that act alone found
defects. This is the pattern the project already uses (`ref/` before the tool): the oracle is the
first client, and the first client finds the awkward edges.

1. **`label-label` without spaces did not assemble.** `msg1end-msg1` was read as one long symbol,
   because the lexer's symbol-terminator set was `:`, space, newline and NUL — not `+` and `-`. With
   spaces it worked, which is why no test had noticed. Fixed in `lcpy`, pinned by the capability pair
   `expr-nospace`.
2. **`cmp r32, [mem]` does not exist** and the compiler needed it immediately (`cmp eax, [rbp+20]`).
   Worked around by loading into a register. It is on the compiler's list for a reason.
3. **`add r32, imm32` does not exist.** `add eax, 48` had to become `mov ecx, 48` + `add eax, ecx`,
   in three places.
4. **`ja`/`jae`/`jbe`/`js`/`jg` do not exist.** Three comparisons had to be inverted by hand; a
   compiler emitting comparisons will want them, and a *compiler* inverting them is fine only while
   the relation is discoverable syntactically.
5. **rel8 is 127 bytes.** Every loop in a 500-line program needs `.l`, and the assembler refuses
   rather than wrapping — which is the right failure, hit five times while writing `cc.s`.
6. **No disp32.** `lea rax, [rbp-40000]` cannot be written; the buffer bases are computed as
   `lea rax, [rbp+1]` then `sub rax, rdx`. A compiler with a frame larger than 127 bytes hits this on
   its first non-trivial function. This is the largest single gap on the assembler side.
7. **Label names are ≤ 7 characters.** `f_mainlab` and `f_return` were rejected at assembly time;
   the compiler now uses `f_hdr` and `f_ret`. A code generator must shorten symbol names, which means
   it needs its own symbol table from day one.
8. **A string on a `db` line ends that line.** `db ":", 10, "db "` silently drops everything after
   the first string. The compiler emits one `db` per item.

And two defects in my own `cc.s`, both the same shape as ones already in the log:

- **`[rbp+8]` (input size) was never initialised.** It only mattered when the input was ≥ 120 bytes,
  because that is when the read loop reads it — so `cc` compiled every small test and refused
  `helloworld.c`. Found by finding the size boundary, not by reading.
- **`mov esi, eax` truncated a 64-bit pointer.** The output buffer is at `rbp-30000`, a stack address;
  `mov esi, eax` kept the low 32 bits and the `write` syscall silently returned `-EFAULT`, so the
  compiler produced no output and exited 0. A compiler must know which of its values are pointers —
  that is a type, and it does not have one.

## The gates for what comes next, in order

Each of these is a *thing a program needs*, and each has a gate that can fail:

| next | what it unblocks | gate |
|---|---|---|
| **`.data`** (second `R+W` `PT_LOAD`, opt-in) | a mutable global, a string built at runtime, a heap | a compiled program that increments a counter in `.data` and prints it; the 18 fixtures stay byte-identical |
| **disp32** in `[base+disp32]` and `lea` | frames and structs over 127 bytes | a compiled function with 200 bytes of locals |
| **`cmp`/`test`/`mov` with `[mem]` operands** | any expression with memory | capability pairs, hand-computed |
| **a calling convention** — args in registers or on the stack, return in `rax`, callee-save rules | `write(...)` becoming a real call; functions at all | a fixture that calls a function with arguments, checks the return value, and would print garbage if the register assignment were wrong |
| **locals, and a frame pointer discipline** | `int x = 5;` | a fixture with two nested calls and a local that survives both |
| **`if`/`while`** | anything interesting | a compiled `while` loop that counts to 10 and prints as `count10` does — the existing fixture becomes the oracle for the *compiler*, not just the assembler |
| **signed condition codes** (done: `jl`/`jle`/`jg`/`jge`/`js`, `idiv`, `cqo`) | `<`, `>`, `<=`, `>=` and signed `/`/`%` on negatives | handwritten hex in `tests/superior/signed.hex` + `tests/differential/` against gcc; see Stage 13 |

The first two are assembler work and are already on `docs/ROADMAP.md`'s compiler list. The third is a
handful of handlers. The fourth is the point at which the C subset stops being a toy: a calling
convention is a *design*, and its gate has to be a program whose output would be wrong if the
registers were assigned differently.

## What this stage is not

- **Not a C compiler.** One function, no expressions, no variables, no control flow, no types.
- **Not self-hosting.** *(Stage 0. Superseded: `src/cc.c`, the same compiler written in the subset,
  is compiled by `cc` and compiles itself; see Stage 11. `src/cc.s` is still its own source and is
  still assembled by `asm1`.)*
- **Not fast, not small.** It reads at most 8000 bytes and writes at most 8000, and refuses beyond
  rather than truncating.

But it *is* the whole pipeline, gated, with a program at the end that prints the right bytes — and the
list above is what the next gates have to be.

## Stage 1: variables and a loop

The subset grew by exactly what the next program needed, and no more:

```
stmt := 'int' 'x' '=' num ';'                 one local, once
      | 'x' '=' 'x' ('+'|'-') num ';'         arithmetic on it
      | 'while' '(' 'x' ')' block             loop while it is non-zero
      | 'write' '(' string ')' ';'
      | 'return' num ';'                      last
```

The emitted code is what a person would write: a prologue (`push rbp` / `mov rbp, rsp`), the local at
`[rbp-8]`, `mov ecx, N` + `add eax, ecx` because `add r32, imm32` does not exist, and loops with
`.l` branches because a loop body can exceed rel8's 127 bytes and the assembler refuses rather than
wraps:

```
L1:
mov eax, [rbp-8]
cmp eax, 0
jz.l L1e
<body>
jmp.l L1
L1e:
```

### The gate for it is a second implementation

`tests/golden/loop.c ` is compiled and compared byte for byte against its golden; the golden is
assembled and **run**; and the compiled program's output is compared against the output of
`tests/oracle/dots.s` — the same program written **by hand in the dialect**, assembled by the same
assembler. Two sources, one behaviour, and neither is produced by the other:

```
  cc    a while loop: same output as the hand-written dialect program
```

That is a different kind of oracle from `ref/`: it does not compare bytes, it compares *meaning*, and
it is the only gate that would notice a compiler bug that emits wrong-but-plausible code for a
construct. It earned its place immediately — the hand-written program segfaulted on `mov r12, 10`,
which is how the `B8+rd`/`REX.W` defect above was found.

## Still not there

- **No expressions.** `x = x + 1 + 1` is not parsed; the right-hand side is exactly `x ± number`.
- **One variable**, named `x`, at a fixed slot.
- **Unsigned semantics only.** `while (x)` is `cmp eax, 0` + `jz`, which is exact for the 0..255 the
  subset allows and would be wrong for negatives — so negatives are not in the subset.
- **No functions, no calls, no `if`.** `write` is still a statement because there is no calling
  convention to call anything with.

## Bootstrap order: what comes after self-hosting

The chain is a chain, and each link is only worth making when the one before it is verified:

| | artifact | source | built by | gate |
|---|---|---|---|---|
| 0 | `asm0a` | — (hand-emitted machine code) | nothing | frozen; sha in `docs/SHAS` |
| 1 | `asm1` | `src/asm1.s` (dialect) | `seed/asm1` | fixpoint, 18 fixtures, 290 pins |
| 2 | `cc` | `src/cc.s` (dialect) | `asm1` | 6 gates, `make test-cc` |
| 3 | a first C tool | `.c` | `cc` + `asm1` | an oracle it inherits, not one it defines |
| 4 | **`cc` in C** | `cc.c` | `cc` + `asm1` | its emitted text must equal the dialect `cc`'s on every golden |
| 5 | **`asm2`** | `src/asm1.c` | `cc` + `asm1` | it must assemble **everything `asm1` does, byte for byte**; then `asm1.s` retires to history like `asm0a` |

Step 5 is `asm1.c -> cc -> asm1 -> asm2`: the assembler rewritten in C, built by the whole chain, and
only then does the dialect implementation become history. Two rules for it:

1. **`asm2` is not accepted until it is byte-identical to `asm1` on the whole corpus** — the 18
   fixtures, the capability pairs, the reject sources, `src/dis.s`, `src/cc.s` and `src/asm1.s`
   itself. `asm1` is the implementation with hand-emitted evidence behind it; a rewrite inherits the
   obligation, not the credit.
2. **The dialect `asm1` is kept, and frozen, not deleted.** It is the only implementation that the
   hand-emitted bytes were checked against, so it stays in the tree the way `asm0a` did — as the
   reference for the rewrite, and as the thing a corrupted `asm2` would be caught by.

Nothing in that order may use a system compiler (invariant 10). The first C compiler has to be
written in the dialect, which is why step 2 precedes step 4 at all.

## Is a linker needed? Not yet, and not in that shape

**No, and it can wait — because the assembler already does the two jobs a linker would do for a
one-unit program, and because the current design cannot use a real one without losing the property
that makes the dialect easy to target.**

A linker does three things. Here is what happens to each:

| a linker | today |
|---|---|
| **symbol resolution** across objects | `asm1`'s label table, in one pass over one input |
| **relocation** — patch addresses whose values are known only at link time | `asm1` evaluates `label`, `label+4`, `end-start` at assembly time, against a fixed base of `0x400000`. There is nothing left to relocate. |
| **section merging** — `.text`, `.data`, `.bss`, alignment, program headers | `asm1` writes the ELF and its program headers itself |

The third row is the design decision that makes the second one invisible: **every address is baked in
as an immediate** (`mov esi, 4194424+label`). That only works while the whole program is one input
with one known layout, which is exactly why a linker is not merely "not yet" — a real one would force
the assembler to stop resolving addresses and emit relocation records instead, and that is the
assembler's single most valuable property gone.

### So how do two translation units get combined?

```
cat a.s b.s | asm1 > a.out
```

That is today's linker, and it works: `main` in `a.s` can `call` a routine defined in `b.s`, because
both end up in one assembly pass with one label table. It is not a link step, it is the absence of one
— the same trick as `#include`.

**It was unsafe until this wave.** Duplicate labels assembled silently, first definition winning, so
`cat main.s other-main.s | asm1` quietly kept one of the two mains. `asm1` now **refuses** a duplicate
definition (`line N: duplicate`), which is what makes concatenation an honest mechanism instead of a
trapdoor. That check cost three deletions first: `src/asm1.s` itself carried seven dead duplicate
labels (a second `chkok`, `trm`'s `termok`/`termnum`, an unreachable `lblchk` block with its own
`ls1`), and the assembler cannot refuse what its own source does.

### When would a linker actually earn its place?

Two cases, and neither is on the compiler's path:

1. **Reusing a runtime across programs** — `write`, `exit`, number formatting as a library. That needs
   no linker: it is one `.s` file `cat`-ed in front, and the label-collision check now makes that
   safe.
2. **Compiling the compiler's own source as several files** — a real linker, or several `cat`s. For a
   compiler of this size one file is fine, and `cat` is fine for two.

What would force it: `.data` as a *separate* segment with its own alignment, or a program large enough
that assembling its source in one pass becomes the bottleneck. Neither is close. The honest position
is the one already in `docs/ROADMAP.md` — **no linker, one translation unit per program** — with
`cat` as the escape hatch and the duplicate check as its guard.

## Stage 2: comparisons, `if`, `else`

```
cond := 'x' | 'x' ('<'|'>'|'<='|'>='|'=='|'!=') num
stmt := 'if' '(' cond ')' block ('else' block)?
      | 'while' '(' cond ')' block
```

No new assembler instruction was needed. The dialect has only `jb`, `jz` and `jnz`, and those three
cover all six relations on **unsigned** values — which is exact for the 0..255 the subset allows:

| source | emitted | why |
|---|---|---|
| `x < N` | `cmp eax, N` / `jb` | carry = "eax below N" |
| `x > N` | `mov ecx, N` / `cmp ecx, eax` / `jb` | the operands swap: "N below x" |
| `x == N` | `cmp eax, N` / `jz` | |
| `x != N` | `cmp eax, N` / `jnz` | |
| `x <= N` | `cmp eax, N+1` / `jb` | normalised; refused when N is 255 |
| `x >= N` | `mov ecx, N-1` / `cmp ecx, eax` / `jb` | refused when N is 0 |

The normalisation is why `x <= 255` and `x >= 0` are **refusals**: both would need a bound outside
0..255. Printing that refusal in the test suite is cheaper than pretending the comparison exists.

Because only "jump if true" is available, each construct is emitted as a jump over its own body:

```
while (x < 5) { B }          if (x == 2) { A } else { B }
L1:                          mov eax, [rbp-8]
mov eax, [rbp-8]             cmp eax, 2
cmp eax, 5                   jz L2t
jb L1b                       jmp.l L2e
jmp.l L1e                    L2t:
L1b:                         A
B                            jmp.l L2x
jmp.l L1                     L2e:
L1e:                         B
                             L2x:
```

Nine block ids, one digit each; a tenth is refused.

### The gates

| # | gate |
|---|---|
| 7 | `branch.c` (a `while (x < 5)` containing `if (x == 2) … else …`) matches its golden **and** prints the same five characters as `tests/oracle/branch.s`, a hand-written dialect program |
| 8 | thirteen inputs outside the subset are refused with no output — including `else if`, `if (x = 1)` and `x <= 255` |

Both were broken on purpose: corrupting the golden's bound fails gate 7 with a diff, and moving the
oracle's dash from `x == 2` to `x == 3` fails it with `[..-..] vs [...-.]`.

### What went wrong, and what it says

Three defects, all mine, all caught by gates rather than reading:

1. **A fragment name that no longer existed** (`f_lp4`, renamed when the loop fragments were replaced)
   — the assembler said `line 417: label`.
2. **The condition's jump instruction and the label share a slot** — `emitnum` clobbers the letter,
   so the emitted jump was `jb L1 ` with a space instead of `jb L1b`.
3. **Nested blocks shared one id counter**, so an `if` inside a `while` emitted the `while`'s exit
   label with the `if`'s id: `line 36: duplicate`, caught by the **duplicate-label check added the
   previous session**. That is the check paying for itself within a day: without it the program would
   have assembled to something that jumped into its own else branch.

## Stage 3: a symbol table, so there can be more than one variable

Eight variables, each with an eight-byte name, at `rbp-16000`; a variable's slot is
`[rbp-8*(index+1)]`. `ident` scans a name (letters, digits, `_`, at most seven characters, not
starting with a digit); `idfind` looks it up; `defvar` refuses a repeat or a ninth; `emit_le` and
`emit_ls` print `mov eax, [rbp-N]` / `mov [rbp-N], eax` with N computed, not hardcoded.

```
int a = 0;        mov eax, 0                 a = b + 3;      mov eax, [rbp-16]
int b = 5;        mov [rbp-8], eax                           mov ecx, 3
                  mov eax, 5                                 add eax, ecx
                  mov [rbp-16], eax                          mov [rbp-8], eax
```

An assignment may name different variables on either side (`a = b + 3`), which fell out of having a
table at all. `cc` 2 902 → 4 386 bytes.

Gate 8 compiles `twovars.c` — two counters, one loop, an `if` on the second — and compares the
binary's output with `tests/oracle/twovars.s`, a hand-written dialect program doing the same thing:

```
  cc    two variables: same output as the hand-written dialect program
```

and 18 inputs are refused, five of them new: an undeclared name, an assignment to an undeclared
name, a repeated declaration, an eight-character name, and a ninth variable.

### The frame: locals live at `[rbp-8k]` without a `sub rsp`

There is no call in the language yet, so nothing pushes over the frame and `[rbp-8k]` is safe without
reserving space. That stops being true the moment a function call exists — and then the frame size has
to be known *before* the prologue is emitted, which means two passes over the input or a patched
prologue. Recording it here because it is the first thing a calling convention will change.

## Stage 4: expressions, with precedence

```
expr := mulk (('+'|'-') mulk)*
mulk := term ('*' term)*
term := number | variable
```

`*` binds tighter than `+`/`-`, left associative, and it is used everywhere an operand used to be:
`int c = a + b * 4;`, `d = c - 5 * 2;`, `return c + d;`.

**One register per nesting depth** — `eax`, `ecx`, `edx`, `esi`, `edi`, `r8d` — so the generated code
carries no stack traffic and a simple expression looks exactly as it always did:

```
a + b * 4          2 + 3 * 4
mov eax, [rbp-8]   mov ecx, 3       (depth 1)
mov ecx, [rbp-16]  mov edx, 4       (depth 2)
mov edx, 4         imul ecx, edx    (combine at depth 1)
imul ecx, edx      add eax, ecx     (combine at depth 0)
add eax, ecx
```

Depth beyond six is refused (there is no parentheses syntax yet, so it is unreachable — a guard, not
a feature). `/` is refused: the dialect has `div r8` only, never `div r32`, so 32-bit division is an
assembler gap, not a compiler one. Recorded in the refusals.

### `return` is now uniform, and that changed every golden

`return N` used to emit `mov eax, 60 / mov edi, N / syscall` with the constant spliced in. With an
expression there is no constant to splice — the value is in `eax` — so every `return` now emits

```
mov edi, eax
mov eax, 60
syscall
```

and a program that falls off the end emits `mov eax, 0` first. One mechanism instead of two, at the
cost of one instruction and of regenerating five goldens. The goldens are regression pins, so
regenerating them is a reviewed act: `hello.s` was read line by line, and every program was run and
its output checked, not just diffed.

Gate 10 is behavioural and would be wrong if precedence were inverted: `return a + b * 4` with
`a = 2, b = 3` must exit **14**. Left-to-right evaluation would give 20.

## Stage 5: a calling convention

The largest remaining decision, and it is now written down and gated:

| | |
|---|---|
| arguments | `rdi`, `rsi`, `rdx`, `rcx` — four, left to right |
| return value | `eax` |
| who copies them | the callee, into its own locals, in the prologue |
| frame | `push rbp` / `mov rbp, rsp` / `sub rsp, 64`; restored before `ret` |
| callee-saved | nothing, because nothing is live across a call |
| temporaries | `eax`, `ecx`, `r8d`, `r9d`, `r10d`, `r11d` — no argument register among them |
| entry point | `entry main`, because `main` is not necessarily the first function |
| `main` | exits; every other function returns |

The callee copying its arguments at entry is the part that earns its keep: `syscall` destroys `rcx`,
so an ABI that left the fourth argument in `rcx` would corrupt it the first time the function wrote
anything. After the prologue the argument registers are dead.

264 bytes of frame is not a guess: it is thirty-two variables of eight bytes, which is the symbol
whole capacity, so the frame cannot be too small for the variables the language can declare.

### The gate is behavioural, and it is about *order*

```
int add(int a, int b) { return a + b; }   int sub2(int a, int b) { return a - b; }
int main(void) { return add(2, 3); }      int main(void) { return sub2(3, 2); }
```

`add(2,3)` must exit **5** and `sub2(3,2)` must exit **1**. Swapping `rdi` and `rsi` gives 5 and
**255**, so an argument-register mistake is a wrong number, not a diff. Verified by corrupting the
golden: `mov rdi, rax` → `mov rsi, rax` produces `calls exited 3/1, wanted 5/1`.

### What this stage does *not* have

- **No call inside a larger expression**, and no call inside an argument list: both are refused,
  because they would clobber argument registers or temporaries. The refusals are in the suite.
- **No recursion yet** — the frame would allow it; what is missing is an argument that is an expression
  (`f(n - 1)`), which is the next step.
- **No forward declarations**: a call to a function defined later still works, because the assembler
  resolves the label, but a call to one that does not exist fails at assembly time (`label`), not at
  compile time.
- **An argument is a whole expression.** `f(3)`, `f(x)`, `f(x + 1)`, `f(n - 1)` and `f(x * 2)` all
  work, and so does `f(a[i])`. This was *not* always so: an argument used to be a pair of terms at
  `eax`/`ecx` in a parser of its own (`argexpr`), because nesting the real one corrupted the symbol
  buffer — which turned out to be the missing stack reservation below. `argexpr` is deleted.

## Stage 6: recursion

`return` is now allowed anywhere a statement is, and the epilogue (or the exit) is emitted in place,
so control leaves the function at that point and anything after it is unreachable. With arguments
that can be `n - 1`, a recursive function works:

```c
int f(int n, int acc)
{
	if (n == 0) { return acc; }
	return f(n - 1, acc + 1);
}
int main(void) { return f(10, 0); }        /* exits 10: ten frames, an accumulator */
```

Gate 13 is behavioural and exact: **10**. A frame that is not restored, or an argument that is not
recomputed per call, gives a wrong number or a crash, never 10.

### The nesting bug, solved

`cc` used to refuse a nested `expr`, because nesting corrupted the symbol-name buffer and the writer
could not be found. It is found: **`cc` never reserved stack** (see "the nesting bug was a missing
`sub rsp`" below). The guard is gone, and so is `argexpr` — the smaller parser written to avoid
nesting. An argument is a whole expression, so `f(x * 2)` works, which it did not before.

What is still refused is narrower and deliberate: **a call only as a whole expression**. `n * f(n-1)`
needs `mov <reg d>, rax` after the call, because a callee returns its value in `rax`.

## Stage 7: 64-bit values, and addresses

A pointer is an address, and an address does not fit in 32 bits. So the value model moved from
32-bit to 64-bit registers in one step that changed **no behaviour at all** — every gate, every exit
code, every byte of output identical — before anything new was built on it:

| | before | after |
|---|---|---|
| value registers | `eax ecx edx esi edi r8d` | `rax rcx rdx rsi rdi r8` |
| a variable | `mov eax, [rbp-8]` | `mov rax, [rbp-8]` |
| combine | `add eax, ecx` | `add rax, rcx` |
| return | `mov edi, eax` | `mov rdi, rax` |
| frame | `mov ecx, 64` / `sub rsp, rcx` | `mov rcx, 64` / `sub rsp, rcx` |

The slots were already eight bytes apart, so nothing moved; only the width of every access changed.
The syscall registers stay as the kernel defines them (`mov eax, 60`, `mov edi, 1`) — those are not
values, they are the ABI.

Then, with 64-bit values, three forms and no type system:

| source | emitted |
|---|---|
| `&x` | `lea rax, [rbp-8]` |
| `*p` | `mov rax, [rbp-16]` / `mov rax, [rax]` |
| `*p = 33` | `mov rax, 33` / `mov rcx, [rbp-16]` / `mov [rcx], rax` |

`*p = expr` computes the **value first** and loads the pointer after it, so nothing is parked: the
value lands in `rax`, the pointer in `rcx`, and one store finishes it. The first version parked the
pointer in a scratch slot for the duration of the expression and reloaded it at 12 bytes a round trip;
that was a second mechanism for a problem the order of two steps already solved.

There is **no pointer type**: an `int` may hold an address, and the compiler neither knows nor checks
which. That is a deliberate deferral — the mechanism (load, store, address-of) is what arrays and a
symbol table need, and the type system is a separate job that changes no emitted code.

Two gates, both exact:

- `int x = 7; int p = &x; int y = *p; *p = 33; return x + y;` → **40**. A wrong stride, a wrong slot or
  a store that misses gives anything else.
- `bump(&x)` where the callee does `*p = *p + 1;` → **42**. The address crosses a call and the callee
  writes into the caller's frame — the thing that makes a pointer useful and the thing an off-by-eight
  frame breaks.

Also fixed while here: `emitreg` copied exactly three characters per register name, so `r8` was
emitted as `r8 ` and `mov r8 , rax` is not a line any assembler should accept. The table is
null-terminated now.

## The nesting bug was a missing `sub rsp`

`cc` never reserved stack. Its prologue was `pop rax; pop rax; lea rbp, [rsp]` and nothing else, so
`rsp == rbp` — and every `call` pushes its return address at `rbp-8`, `rbp-16`, … straight into the
region where `cc` keeps its state (`-100` … `-264`). The slots survived only because no parse path had
ever been deeper than twelve calls. Adding one call (`exprd`) to the variable-argument path pushed it
over, and `cc` started refusing `f(x)` — which is how the bug was found, not by reading.

**The fix is two instructions and a number:**

```
lea rbp, [rsp]
mov ecx, 320
sub rsp, rcx        ; every call pushes at rbp-8, -16, ...; the state is at -100..-264
```

**And it is the nesting bug.** With the reserve in place, the parse that had corrupted the symbol-name
buffer runs to completion: replacing `argexpr` with `exprd` in the argument loop makes every golden
byte-identical except `recursion`, which differs by two blank lines. The "value 1 where a variable's
name should have been" was a state slot overwritten by a return address — `[rbp-208]`, the
"inside an argument list" flag, is exactly `1`.

The guard (`cc: internal: nested expression`) enforced a constraint that no longer held, so it is
gone, together with `argexpr` — the smaller parser written to avoid nesting. An argument is a whole
expression now, which is what made `f(x * 2)` work. The 14 goldens were re-pinned; `recursion`
differed only by two blank lines, which is what a deleted routine's trailing newline looks like.

## Stage 8: arrays

`int a[4];` allocates four consecutive slots, and `a[i]` addresses one of them:

| source | emitted |
|---|---|
| `int a[4];` | four slots; allocator 400→432, stored end 432, so `a` is `[rbp-432]` and `a[3]` is `[rbp-408]` |
| `a[i]` | `lea rcx, [rbp-432]` / index at the next depth / `add rcx, rcx` ×3 / `add rax, rcx` / `mov rax, [rax]` |
| `a[i] = v` | the value first, then `lea rcx, [rbp-432]` / `add rcx, <scaled index>` / `mov [rcx], rax` |

The base is the array's **end** (`rbp-end`), so the index walks up into the reserved region and
never past `rbp`; `tests/golden/arrlocal.c` pins that with a 900-byte array in a callee.

The base sits in `reg d` while the index is computed at `d+1` — that is what the depth mechanism is
for — which needed one new routine, `exprd`: an expression at a caller-given depth.

```
exprd:
mov [rbp-128], eax
call ex1
ret
```

Three refusals came out of doing it: a bare array name (`a = 1`, `int y = a;`) because silently
reading `a[0]` is a wrong answer; a subscript of something that is not an array; and an array too big
for the free slots. A **nested** subscript (`a[b[0]]`) is refused too, because it re-enters the
parser from inside a term — the shape that used to corrupt state. Now that the cause is known that
refusal is probably unnecessary; it stays until a test can show it is safe.

Still absent, deliberately: no bounds check, no arrays as function arguments (a bare name is refused),
and no initialiser list; arrays share the 32-slot symbol budget with scalars.

Gates: 42 from `a[0] = 10; a[i] = 32; return a[0] + a[i];` with `i = 2` — a wrong stride, base or slot
gives anything else — and 42 from `f(a[i])`, an element crossing a call.

## Stage 9: a call inside a larger expression

`n * f(n - 1)` works now, so recursion is ordinary rather than tail-shaped. Two things were needed,
and the second is the interesting one:

1. **The result arrives in `rax`**, which is depth 0's register. A call at depth `d` therefore moves
   it: `mov <reg d>, rax`.
2. **The call destroys `rax`, `rcx`, `rdx` and `rsi`** — and `reg 0..d-1` hold the operands of the
   expressions enclosing it. They are pushed before the call and popped after it, in reverse:

```
mov rax, [rbp-8]        ; n            (depth 0)
push rax                ; save it: fact() will return in rax
mov rdx, [rbp-8]        ; the argument, at depth 2
mov rsi, 1
sub rdx, rsi
mov rdi, rdx
call fact
mov rcx, rax            ; the result to depth 1
pop rax                 ; n back
imul rax, rcx
```

At depth 0 there is nothing live, so the common case — `f(x)` as a whole expression — emits no push
at all. Arguments are evaluated at `d+1` so they cannot touch `reg 0..d`; that needed an "argument
depth" slot (`[rbp-292]`), set by `ex3call`.

Gates, both exact: `fact(5)` → **120** (a call inside a product) and `sum(4)` → **10** (a call inside a
sum). A missing push gives a square or a doubled value, never 120; a wrong result register gives
garbage from `rcx`.

Three defects while building it, all found by reading the emitted text rather than by testing:

- The argument counter lost its `inc` when the loop was rewritten, so five arguments were accepted —
  a *refusal* regressed, which is the sort of thing only a refusal test catches.
- `exprd` leaves `[rbp-128]` at the depth it was given, so `a[0] + a[i]` combined at the wrong depth
  (`add rdx, rsi`). The restore `mov [rbp-128], <d>` is required after every nested parse.
- `stptr` read its slot offset from `[rbp-140]`, the shared term scratch, after `expr` had overwritten
  it — `mov rcx, [rbp-33]`. Fixed by never reading a shared scratch after a nested parse.

## The frame slots, and the rule they taught

`cc` keeps its state in fixed slots off `rbp`. Four defects in three waves were the same defect: **a
slot shared across a nested parse.** The rule is that a value must survive every call that runs
between its two uses — and `expr`, `exprd`, `want`, `skipws`, `emitstr`, `emitnum` and `emitreg` all
run between them.

| slot | owner | safe across a nested parse? |
|---|---|---|
| `-100` … `-120` | ident: name length, scan index, variable count, scratch | yes, but `ident` resets them |
| `-128` | the expression **depth** | **no** — `exprd` sets it to its argument |
| `-132` | the operator being combined | yes: set after the nested parse |
| `-140` | value/offset of the current term | **no** — every term writes it |
| `-144` `-148` | `emitreg` scratch | no |
| `-160` `-164` `-168` `-176` | function label, is-main, argument index, param index | yes |
| `-192` | `emitname`'s pointer | yes: set and used immediately |
| `-200` `-204` | the callee's name, saved across its arguments | yes |
| `-208` | inside an argument list | yes (a flag) |
| `-236` | inside a subscript | yes (a flag) |
| `-244` | `stptr`'s slot offset | **no** — a later fixed version |
| `-256` … `-300` | arrays: count, base, loop counters, `d`, argument depth | yes if the name says so |
| `-14000` | array flags, one byte per slot | yes |
| `-16000` `-16060` / `-16064` | the symbol table / the name being scanned | yes |
| `-20000` | literal table | yes |
| `-30000` `-40000` | output buffer, input buffer | yes |

And the `sub rsp, 320` under all of it: a slot above `rsp` is safe from pushes, a slot below it is
not. `-100` … `-264` are above; the buffers are below and are safe only because no call chain
reaches 1 750 frames.

## Stage 10: `char` arrays

`char a[N];` allocates `ceil(N/8)` slots and uses one byte of each element:

| source | emitted |
|---|---|
| `char a[4];` | one slot: allocator 400→408, base `[rbp-408]`, `a[0]`..`a[3]` at `rbp-408`..`rbp-405` |
| `a[i]` | `lea rax, [rbp-408]` / the index / **no stride** / `add rax, rcx` / `movzx rax, byte [rax]` |
| `a[i] = v` | the value first, then the address / `mov [rcx], al` |

The only new idea is that the *element size* is the kind: the flags table stores 8 for an int array
and 1 for a char array, so one field answers both "is this an array" and "how big is an element".
Allocation converts elements to slots without a branch:

```
mov ecx, <elements>
mov edx, [rbp-304]      ; the element size: 8 or 1
imul ecx, edx           ; bytes
mov edx, 7
add ecx, edx
shr ecx, 3              ; slots
```

Gates: `a[0] = 65; a[i] = 66` with `i = 1` exits **131** (a wrong stride or width gives anything else),
and `char a[9]` beside `int b = 7` with `a[8] = 65` exits **72** — which only holds if the nine-byte
array occupies exactly two slots, because a char array that overran would overwrite `b` and the sum
would be 130.

Refused, deliberately: a `char` scalar (`char x = 65;`), because there is no type system to say what
it means and a symbol table needs a byte *buffer*, not a byte variable.

`add r32, imm` does not exist in the dialect, which is why the allocation above loads 7 into a
register. That gap has now cost three separate workarounds in `cc` and is the next thing `asm1`
should learn.

## Stage 11: the port compiles itself

`src/cc.c` is the same compiler, written in the subset it compiles. It is not a sketch: it
implements the whole subset above — scanner, symbol table, arrays, expressions with precedence,
division, calls, recursion, conditions, literals, `read`/`write`, and the new `exit` builtin — and it
emits the same text as `src/cc.s` does.

The proof is two targets, and they are different claims:

```
make test-port    43/43 goldens byte-identical to cc, and the port-built putn prints 4321
make test-d2      THE PORT COMPILES ITSELF -- cc1.s and cc2.s are identical, 129752 bytes
```

`test-port` builds `cc1` (`cc < src/cc.c` then `asm1`) and compiles every committed `.c` golden and
`helloworld.c` with it, comparing each output with the golden `cc` produced. That is equivalence, not
just self-consistency: a port that disagreed with the dialect compiler would be pinning the wrong
text. `test-d2` then runs `cc1 < src/cc.c` and compares with `cc1.s`; a correct compiler is
deterministic, so the two must be identical.

**One language addition: `exit(n)`.** The subset's only way out of a program was `return` from
`main`, and a compiler needs to stop from inside `fail`. `exit` emits the same three instructions
`main`'s return does, and is gated by `tests/golden/exit.c` (exits 3, writes nothing).

### How the port is built inside the subset

All state lives in one `char mem[31500]`, addressed through one `int` pointer, because a scalar
pointer subscript is a **byte** subscript in this dialect: an `int` array cannot cross a call. Values
wider than a byte are two bytes little-endian (`gw`/`pw` for the state block, `gwa`/`pwa` for the
tables). Names, symbol entries, literal entries and the state block have fixed offsets in that one
buffer; the offsets are at the top of the file.

Two passes: the first parses with `EM = 0`, so every emitter discards, and a refusal exits 1 with no
bytes written; the second resets the cursor, literal counter, block id and array allocator, sets
`EM = 1`, and parses again. The output is written one byte at a time with the `write` builtin, so
there is no output buffer to overrun.

### The five things the port found in the compiler it is porting

1. **Arrays used to be addressed upward from `rbp-off`.** A buffer of size `B` declared when the
   allocator was at `off` occupied `[rbp-off, rbp-off+B)`; it stayed below `rbp` only when `B <= off`.
   A 31 KB buffer declared first would run through the return address. This was fixed while preparing
   `asm1.c`: the allocator now stores the array's **end**, so base = `rbp-end` and index `i` lands at
   `rbp-end+i`, inside the reserved region. The port's `char mem[31500]` is enough on its own; the
   `pad` array that used to move its base is gone. Gate: `tests/golden/arrlocal.c`.
2. **A subscript in the value of an array store overwrites the left side's saved kind.** `st_sub`
   keeps `kind` in `[rbp-308]`; `ex3sub` uses the same slot for its own result. `nm[k] = m[...]`
   therefore emits `mov rcx, [rbp-408]` (load the first eight bytes of `nm` as an address) instead of
   `lea rcx, [rbp-408]`. `src/cc.c` reads through a temporary; the dialect `cc` still has the defect.
3. **A call in an argument list is refused** (`f(g(x))`), so staging through a local is not optional.
4. **State-field overlap**: `AD` is a 16-bit field at offset 27, so writing it also writes offset 28.
   `EM` was at 28 in the first version, and the first call silently switched emission off. `EM` is 29.
5. **The frame is 65 536 and arrays are cumulative across functions**: `mem` (31 500) plus the
   helper functions' `b[8]` and `nm[16]` total 31 554, well under the 64 000-byte array limit.

### What the port is not

- Its input cap is **26 000 bytes** (`src/cc.c` is 24 297); a source that fills the buffer is refused,
  not truncated — a full buffer cannot be told from a truncated one.
- A refusal is `exit(1)` with **no stderr text**; the subset's `write` is fd 1 only, and adding a
  fd-2 builtin would be a second mechanism for a message the dialect compiler still prints.
- It is a port of this compiler, not a new design: it keeps the same ABI, the same emitted text, and
  the same accepted subset.

The next bootstrap step is `asm2`: rewrite `asm1` in C, build it with `cc` + `asm1`, and accept it
only when it assembles everything `asm1` does, byte for byte. `src/cc.c` is step 4 of that chain;
step 5 has not started.

## Stage 12: the assembler in C (`asm2`)

`src/asm1.c` is the assembler written in the same subset: three passes (labels, count with labels,
emit), the 120-byte ELF64 header, labels to 2 048, input to 200 000, and the exact `line N: reason`
messages (`range`, `label`, `duplicate`, `rejected`). It is built by the chain

```
cc < src/asm1.c > asm1.c.s ; asm1 < asm1.c.s > asm2
```

and `make test-asm2` requires it to reproduce `asm1` on the whole corpus — 17 hand-emitted
references, 80 capability/superior inputs, 100 coverage forms, 9 refusals, 8 exact messages,
`src/dis.s`, `src/cc.s`, `src/asm1.s`, the 99 032-byte source (and run, exit 42) — and then to
assemble the text of its own compiler into itself:

```
  asm2: 234 checks, 0 failures -- corpus and self-assembly
```

Building it forced three compiler changes that are part of the record: numeric literals to
16 777 215 and eight-digit `emitnum`; condition jumps emitted as `.l` (a rel8 condition around a
large block is an overflow, not a hypothetical); and `werr(buf, n)`, the fd-2 builtin that names a
line and a reason. The frame moved to 260 000 and arrays to 255 000 so a 200 KB source and a
2 048-label table fit. `asm1` is **not deleted**: it is the witness the hand-emitted references and
every earlier record were checked against, and `asm2` inherits the obligation, not the credit.

The next decision is whether `make` should build the assembler from `src/asm1.c` and what `seed/`
means after that; the next feature is `.data`.

## Stage 13: signed comparisons and division

The language now means what a C programmer expects for signed values: source `<` emits `jl`, `>`
emits `jg`, `<=`/`>=` are normalised to `<`/`>` with an adjusted bound, and `/`/`%` emit `cqo` +
`idiv` (truncating toward zero). The dialect compiler no longer silently gives a negative value
unsigned semantics.

The assembler gained `jl/jle/jg/jge/js` (rel8 and `.l`), `cqo` and `idiv r32/r64`, each with a
hand-written hex expectation in `tests/superior/signed.hex` and a coverage row. `src/asm1.s` is
frozen; the live source is `src/asm1.c`.

Two signed-compiler defects surfaced while making the compiler build itself:

- `pd`/`pda`/`pw`/`pwa` split values with `/ 256`; signed division truncates toward zero, so a
  negative value wrote zero high bytes. They now shift arithmetically.
- `ex4`/`ex8` had the same defect for rel32 and disp32, which showed up as `0x00` where the corpus
  expected `0xff` in `callret.s` and `rel32.s`.

The compiler's own internal comparisons are on non-negative counts and offsets, so signed emission is
safe for them; that is stated at `condjump`. `calc.c` was rewritten to use `v < 0` and signed `/`
and `%`, deleting the magnitude workaround, and its table now includes `(3-10)/2` and `(3-10)%3`.

### The differential

`tools/differential.sh` is the fourth oracle rung. It builds each `tests/differential/*.c` with both
`cc`+`asm1` and `gcc -O0 -funsigned-char`, then compares stdout bytes and exit status. gcc builds
only the second opinion; it never produces a repository artifact. It is a named exemption in
`make test-tools` and is run by hand, not from `make check`.

```
tools/differential.sh                5/5 AGREE
tools/differential.sh seed/cc ./asm1 1/5 (the pre-signed dialect witness DIFFERS on all four negative cases)
```

That failure against the old compiler is why the gate can be trusted: a green run is not a format
check wearing a gate's clothes.
