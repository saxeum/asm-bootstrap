# The compiler: `helloworld.c` to a running binary, and the gates it forces

This is the plan for the second half of the project: a **compiler** whose target is this dialect. It
starts with the smallest complete example, because compiling `helloworld.c` end to end already says
what every gate has to be.

## One command, and the mistake it prevents

```
make hello
```

prints `Hello, World!`. That is a two-stage pipeline underneath, and the second stage is easy to
forget:

```
./cc < helloworld.c > hello.s     the compiler writes dialect TEXT
./asm1 < hello.s > hello          the assembler is what makes a program
```

Forgetting it means running a text file full of assembly as a shell script, which answers with
`command not found` once per line and no hint about why. So the emitted text begins with:

```
; generated by cc: dialect source, not a program. Assemble it with asm1
```

A leading `;` is a comment to the assembler and a **syntax error to the shell**, so the mistake now
fails on line 1 and quotes the sentence that explains it. That line is part of the golden text, so it
is pinned like everything else the compiler emits.

## The design decision

**The compiler emits dialect source, not machine code.** Three consequences, and they are the
reason:

1. **The output is reviewable.** A compiler that emits text can be diffed, read and argued about; one
   that patches an ELF cannot. Every mistake in the backend is a visible line of assembly.
2. **`asm1` stays the only byte-producer.** Encoding correctness is already gated by 18 fixtures, 12
   rejections, 30 capability pairs, 88 coverage forms, 5 superiority cases and the fixpoint. A
   compiler emitting bytes directly would need all of that again, for itself.
3. **The gates are cheap.** `cmp` against a golden text file; `cmp` against the machine's output.

## The subset, exactly (stage 0)

```
program  := decl
decl     := 'int' 'main' '(' 'void' ')' block
block    := '{' stmt* '}'
stmt     := 'write' '(' string ')' ';'
          | 'return' number ';'          (last statement only, optional)
string   := '"' any-bytes-except-quote '"'
number   := decimal 0..255
comment  := '/*' ... '*/'  |  '//' ... end-of-line
```

Semantics, which is the whole ABI at this size:

| source | meaning |
|---|---|
| `write("s")` | `syscall` 1, fd 1, the address of a `db` holding the literal's bytes, length = `end-start` |
| `return N` | `syscall` 60 with status N |
| nothing after `}` | required; trailing tokens are refused |
| no `return` | exit 0 |
| up to 9 `write`s | one label pair per literal, `m1`/`m1end` … |

`write` is a **statement, not a call**, and that is the honest part of stage 0: there is no calling
convention yet, so a function call cannot be compiled. Turning `write(...)` into a call is gate 5
below.

## The output text, which is a designed artefact

The emitted text has one shape, and `tests/golden/hello.s` is its specification:

```
; generated by cc: dialect source, not a program. Assemble it with asm1
main:
mov eax, 1
mov edi, 1
mov esi, 4194424+m1
mov edx, m1end-m1
syscall
mov eax, 60
mov edi, 0
syscall
m1:
db "Hello, World!\n"
m1end:
```

Four things are chosen deliberately:

- **The first line is a comment** that says what the file is, because a pipeline with two stages
  invites running the first stage's output. A leading `;` is a shell syntax error, which is the
  loudest thing that can happen to a text file that is not a program.
- **`4194424+m1`** is `0x400078 + label`, the first body byte plus the label's offset: the dialect
  knows a label's value as an offset, and the image is loaded at a fixed address.
- **`m1end-m1`** is the string length as a label difference, so the compiler never counts bytes.
  This is what the expression support was built for, and it is why `label-label` had to lex without
  spaces (see the defect below).
- **All code, then all data.** A `db` between two `syscall`s would be *executed* when the write
  returns. So literals are collected during the parse and emitted after the exit block.

## The gates

```
make test-cc
```

| # | gate | fails when |
|---|---|---|
| 1 | `cc < helloworld.c` is byte-identical to `tests/golden/hello.s` | the emitted text changes shape |
| 2 | `asm1 < tests/golden/hello.s` produces a binary | the golden is not assemblable |
| 3 | that binary writes exactly `Hello, World!\n` and exits 0 | the semantics are wrong |
| 4 | a second program (two writes, `return 255`) matches its own golden and runs | only one case ever works |
| 5 | a compiled `while` loop matches its golden **and** the output of a hand-written dialect program | the compiler emits plausible wrong code, or the loop is wrong |
| 6 | ten inputs outside the subset are refused, with no output | the front end guesses |

Gate 3 is what makes gate 1 mean anything. The golden cannot be an *oracle* for its own text — it is
a regression pin, and its validity rests on the machine judging the binary it assembles to. That is
the same split as `ref/`: bytes are pinned by a hand-written expectation, meaning is pinned by
execution.

Gates 1 and 3 were both checked by breaking them: a one-byte change to the golden fails gate 1 with a
diff, and changing the string to `Hello, World?` fails gate 1 *and* gate 3 (`the binary exited 0 and
wrote [Hello, World?]`).

## What writing the oracle found in the assembler

The C file and its hand-written golden were written before the compiler, and that act alone found
defects. This is the pattern the project already uses (`ref/` before the tool): the oracle is the
first client, and the first client finds the awkward edges.

1. **`label-label` without spaces did not assemble.** `msg1end-msg1` was read as one long symbol,
   because the lexer's symbol-terminator set was `:`, space, newline and NUL — not `+` and `-`. With
   spaces it worked, which is why no test had noticed. Fixed in `lcpy`, pinned by the capability pair
   `expr-nospace`.
2. **`cmp r32, [mem]` does not exist** and the compiler needed it immediately (`cmp eax, [rbp+20]`).
   Worked around by loading into a register. It is on the compiler's list for a reason.
3. **`add r32, imm32` does not exist.** `add eax, 48` had to become `mov ecx, 48` + `add eax, ecx`,
   in three places.
4. **`ja`/`jae`/`jbe`/`js`/`jg` do not exist.** Three comparisons had to be inverted by hand; a
   compiler emitting comparisons will want them, and a *compiler* inverting them is fine only while
   the relation is discoverable syntactically.
5. **rel8 is 127 bytes.** Every loop in a 500-line program needs `.l`, and the assembler refuses
   rather than wrapping — which is the right failure, hit five times while writing `cc.s`.
6. **No disp32.** `lea rax, [rbp-40000]` cannot be written; the buffer bases are computed as
   `lea rax, [rbp+1]` then `sub rax, rdx`. A compiler with a frame larger than 127 bytes hits this on
   its first non-trivial function. This is the largest single gap on the assembler side.
7. **Label names are ≤ 7 characters.** `f_mainlab` and `f_return` were rejected at assembly time;
   the compiler now uses `f_hdr` and `f_ret`. A code generator must shorten symbol names, which means
   it needs its own symbol table from day one.
8. **A string on a `db` line ends that line.** `db ":", 10, "db "` silently drops everything after
   the first string. The compiler emits one `db` per item.

And two defects in my own `cc.s`, both the same shape as ones already in the log:

- **`[rbp+8]` (input size) was never initialised.** It only mattered when the input was ≥ 120 bytes,
  because that is when the read loop reads it — so `cc` compiled every small test and refused
  `helloworld.c`. Found by finding the size boundary, not by reading.
- **`mov esi, eax` truncated a 64-bit pointer.** The output buffer is at `rbp-30000`, a stack address;
  `mov esi, eax` kept the low 32 bits and the `write` syscall silently returned `-EFAULT`, so the
  compiler produced no output and exited 0. A compiler must know which of its values are pointers —
  that is a type, and it does not have one.

## The gates for what comes next, in order

Each of these is a *thing a program needs*, and each has a gate that can fail:

| next | what it unblocks | gate |
|---|---|---|
| **`.data`** (second `R+W` `PT_LOAD`, opt-in) | a mutable global, a string built at runtime, a heap | a compiled program that increments a counter in `.data` and prints it; the 18 fixtures stay byte-identical |
| **disp32** in `[base+disp32]` and `lea` | frames and structs over 127 bytes | a compiled function with 200 bytes of locals |
| **`cmp`/`test`/`mov` with `[mem]` operands** | any expression with memory | capability pairs, hand-computed |
| **a calling convention** — args in registers or on the stack, return in `rax`, callee-save rules | `write(...)` becoming a real call; functions at all | a fixture that calls a function with arguments, checks the return value, and would print garbage if the register assignment were wrong |
| **locals, and a frame pointer discipline** | `int x = 5;` | a fixture with two nested calls and a local that survives both |
| **`if`/`while`** | anything interesting | a compiled `while` loop that counts to 10 and prints as `count10` does — the existing fixture becomes the oracle for the *compiler*, not just the assembler |
| **signed condition codes `ja/jae/js/jg/jo`** | `<`, `>`, `<=`, `>=` on signed integers | handwritten golden text + a program that takes the right branch on negatives |

The first two are assembler work and are already on `docs/ROADMAP.md`'s compiler list. The third is a
handful of handlers. The fourth is the point at which the C subset stops being a toy: a calling
convention is a *design*, and its gate has to be a program whose output would be wrong if the
registers were assigned differently.

## What this stage is not

- **Not a C compiler.** One function, no expressions, no variables, no control flow, no types.
- **Not self-hosting.** `cc.s` is ~500 lines of dialect assembled by `asm1`; it does not compile
  itself, and it will not for a long time.
- **Not fast, not small.** It reads at most 8000 bytes and writes at most 8000, and refuses beyond
  rather than truncating.

But it *is* the whole pipeline, gated, with a program at the end that prints the right bytes — and the
list above is what the next gates have to be.

## Stage 1: variables and a loop

The subset grew by exactly what the next program needed, and no more:

```
stmt := 'int' 'x' '=' num ';'                 one local, once
      | 'x' '=' 'x' ('+'|'-') num ';'         arithmetic on it
      | 'while' '(' 'x' ')' block             loop while it is non-zero
      | 'write' '(' string ')' ';'
      | 'return' num ';'                      last
```

The emitted code is what a person would write: a prologue (`push rbp` / `mov rbp, rsp`), the local at
`[rbp-8]`, `mov ecx, N` + `add eax, ecx` because `add r32, imm32` does not exist, and loops with
`.l` branches because a loop body can exceed rel8's 127 bytes and the assembler refuses rather than
wraps:

```
L1:
mov eax, [rbp-8]
cmp eax, 0
jz.l L1e
<body>
jmp.l L1
L1e:
```

### The gate for it is a second implementation

`tests/golden/loop.c ` is compiled and compared byte for byte against its golden; the golden is
assembled and **run**; and the compiled program's output is compared against the output of
`tests/oracle/dots.s` — the same program written **by hand in the dialect**, assembled by the same
assembler. Two sources, one behaviour, and neither is produced by the other:

```
  cc    a while loop: same output as the hand-written dialect program
```

That is a different kind of oracle from `ref/`: it does not compare bytes, it compares *meaning*, and
it is the only gate that would notice a compiler bug that emits wrong-but-plausible code for a
construct. It earned its place immediately — the hand-written program segfaulted on `mov r12, 10`,
which is how the `B8+rd`/`REX.W` defect above was found.

## Still not there

- **No expressions.** `x = x + 1 + 1` is not parsed; the right-hand side is exactly `x ± number`.
- **One variable**, named `x`, at a fixed slot.
- **Unsigned semantics only.** `while (x)` is `cmp eax, 0` + `jz`, which is exact for the 0..255 the
  subset allows and would be wrong for negatives — so negatives are not in the subset.
- **No functions, no calls, no `if`.** `write` is still a statement because there is no calling
  convention to call anything with.

## Bootstrap order: what comes after self-hosting

The chain is a chain, and each link is only worth making when the one before it is verified:

| | artifact | source | built by | gate |
|---|---|---|---|---|
| 0 | `asm0a` | — (hand-emitted machine code) | nothing | frozen; sha in `docs/SHAS` |
| 1 | `asm1` | `src/asm1.s` (dialect) | `seed/asm1` | fixpoint, 18 fixtures, 290 pins |
| 2 | `cc` | `src/cc.s` (dialect) | `asm1` | 6 gates, `make test-cc` |
| 3 | a first C tool | `.c` | `cc` + `asm1` | an oracle it inherits, not one it defines |
| 4 | **`cc` in C** | `cc.c` | `cc` + `asm1` | its emitted text must equal the dialect `cc`'s on every golden |
| 5 | **`asm2`** | `src/asm1.c` | `cc` + `asm1` | it must assemble **everything `asm1` does, byte for byte**; then `asm1.s` retires to history like `asm0a` |

Step 5 is `asm1.c -> cc -> asm1 -> asm2`: the assembler rewritten in C, built by the whole chain, and
only then does the dialect implementation become history. Two rules for it:

1. **`asm2` is not accepted until it is byte-identical to `asm1` on the whole corpus** — the 18
   fixtures, the capability pairs, the reject sources, `src/dis.s`, `src/cc.s` and `src/asm1.s`
   itself. `asm1` is the implementation with hand-emitted evidence behind it; a rewrite inherits the
   obligation, not the credit.
2. **The dialect `asm1` is kept, and frozen, not deleted.** It is the only implementation that the
   hand-emitted bytes were checked against, so it stays in the tree the way `asm0a` did — as the
   reference for the rewrite, and as the thing a corrupted `asm2` would be caught by.

Nothing in that order may use a system compiler (invariant 10). The first C compiler has to be
written in the dialect, which is why step 2 precedes step 4 at all.

## Is a linker needed? Not yet, and not in that shape

**No, and it can wait — because the assembler already does the two jobs a linker would do for a
one-unit program, and because the current design cannot use a real one without losing the property
that makes the dialect easy to target.**

A linker does three things. Here is what happens to each:

| a linker | today |
|---|---|
| **symbol resolution** across objects | `asm1`'s label table, in one pass over one input |
| **relocation** — patch addresses whose values are known only at link time | `asm1` evaluates `label`, `label+4`, `end-start` at assembly time, against a fixed base of `0x400000`. There is nothing left to relocate. |
| **section merging** — `.text`, `.data`, `.bss`, alignment, program headers | `asm1` writes the ELF and its program headers itself |

The third row is the design decision that makes the second one invisible: **every address is baked in
as an immediate** (`mov esi, 4194424+label`). That only works while the whole program is one input
with one known layout, which is exactly why a linker is not merely "not yet" — a real one would force
the assembler to stop resolving addresses and emit relocation records instead, and that is the
assembler's single most valuable property gone.

### So how do two translation units get combined?

```
cat a.s b.s | asm1 > a.out
```

That is today's linker, and it works: `main` in `a.s` can `call` a routine defined in `b.s`, because
both end up in one assembly pass with one label table. It is not a link step, it is the absence of one
— the same trick as `#include`.

**It was unsafe until this wave.** Duplicate labels assembled silently, first definition winning, so
`cat main.s other-main.s | asm1` quietly kept one of the two mains. `asm1` now **refuses** a duplicate
definition (`line N: duplicate`), which is what makes concatenation an honest mechanism instead of a
trapdoor. That check cost three deletions first: `src/asm1.s` itself carried seven dead duplicate
labels (a second `chkok`, `trm`'s `termok`/`termnum`, an unreachable `lblchk` block with its own
`ls1`), and the assembler cannot refuse what its own source does.

### When would a linker actually earn its place?

Two cases, and neither is on the compiler's path:

1. **Reusing a runtime across programs** — `write`, `exit`, number formatting as a library. That needs
   no linker: it is one `.s` file `cat`-ed in front, and the label-collision check now makes that
   safe.
2. **Compiling the compiler's own source as several files** — a real linker, or several `cat`s. For a
   compiler of this size one file is fine, and `cat` is fine for two.

What would force it: `.data` as a *separate* segment with its own alignment, or a program large enough
that assembling its source in one pass becomes the bottleneck. Neither is close. The honest position
is the one already in `docs/ROADMAP.md` — **no linker, one translation unit per program** — with
`cat` as the escape hatch and the duplicate check as its guard.

## Stage 2: comparisons, `if`, `else`

```
cond := 'x' | 'x' ('<'|'>'|'<='|'>='|'=='|'!=') num
stmt := 'if' '(' cond ')' block ('else' block)?
      | 'while' '(' cond ')' block
```

No new assembler instruction was needed. The dialect has only `jb`, `jz` and `jnz`, and those three
cover all six relations on **unsigned** values — which is exact for the 0..255 the subset allows:

| source | emitted | why |
|---|---|---|
| `x < N` | `cmp eax, N` / `jb` | carry = "eax below N" |
| `x > N` | `mov ecx, N` / `cmp ecx, eax` / `jb` | the operands swap: "N below x" |
| `x == N` | `cmp eax, N` / `jz` | |
| `x != N` | `cmp eax, N` / `jnz` | |
| `x <= N` | `cmp eax, N+1` / `jb` | normalised; refused when N is 255 |
| `x >= N` | `mov ecx, N-1` / `cmp ecx, eax` / `jb` | refused when N is 0 |

The normalisation is why `x <= 255` and `x >= 0` are **refusals**: both would need a bound outside
0..255. Printing that refusal in the test suite is cheaper than pretending the comparison exists.

Because only "jump if true" is available, each construct is emitted as a jump over its own body:

```
while (x < 5) { B }          if (x == 2) { A } else { B }
L1:                          mov eax, [rbp-8]
mov eax, [rbp-8]             cmp eax, 2
cmp eax, 5                   jz L2t
jb L1b                       jmp.l L2e
jmp.l L1e                    L2t:
L1b:                         A
B                            jmp.l L2x
jmp.l L1                     L2e:
L1e:                         B
                             L2x:
```

Nine block ids, one digit each; a tenth is refused.

### The gates

| # | gate |
|---|---|
| 7 | `branch.c` (a `while (x < 5)` containing `if (x == 2) … else …`) matches its golden **and** prints the same five characters as `tests/oracle/branch.s`, a hand-written dialect program |
| 8 | thirteen inputs outside the subset are refused with no output — including `else if`, `if (x = 1)` and `x <= 255` |

Both were broken on purpose: corrupting the golden's bound fails gate 7 with a diff, and moving the
oracle's dash from `x == 2` to `x == 3` fails it with `[..-..] vs [...-.]`.

### What went wrong, and what it says

Three defects, all mine, all caught by gates rather than reading:

1. **A fragment name that no longer existed** (`f_lp4`, renamed when the loop fragments were replaced)
   — the assembler said `line 417: label`.
2. **The condition's jump instruction and the label share a slot** — `emitnum` clobbers the letter,
   so the emitted jump was `jb L1 ` with a space instead of `jb L1b`.
3. **Nested blocks shared one id counter**, so an `if` inside a `while` emitted the `while`'s exit
   label with the `if`'s id: `line 36: duplicate`, caught by the **duplicate-label check added the
   previous session**. That is the check paying for itself within a day: without it the program would
   have assembled to something that jumped into its own else branch.
