# The encoding standard

Every opcode this assembler emits is checked against **ref.x86asm.net** — the *X86 Opcode and
Instruction Reference*, whose primary source is an XML document rather than HTML tables.

**Not vendored.** The dataset is GPL-3.0 and this repository has no license yet, so
redistributing it here would decide licensing for the whole project. That is the owner's
call, not a build detail. It is fetched locally instead:

```bash
mkdir -p .refcache
curl -sSL http://ref.x86asm.net/x86reference.xml -o .refcache/x86reference.xml
sha256sum .refcache/x86reference.xml      # must match the sha256 above
```

`.refcache/` is in `.gitignore`. What *is* committed is this file: our own derived table of
the forms we emit, which is the thing that has to stay in sync with the assembler.

## What this standard can and cannot tell us

- **Can**: which primary opcode and which `/digit` group extension belong to a mnemonic and
  operand *shape* (the `<a>`/`<t>` codes: `Z`=opcode+reg, `E`=modrm r/m, `G`=modrm reg,
  `I`=immediate, `J`=relative), and which *modes* an opcode is valid in.
- **Cannot**: whether our ModRM/REX bits, displacement sizes and immediates are right. The
  reference constrains the operand *shape*; the bit-level encodings still need `objdump` (an
  independent decoder) and execution (the machine). See `docs/oracles.md` for why those are
  different rungs.

**29 forms, 0 problems.**

Two findings the query produced that are worth keeping:

1. **`0F 05` is mode-dependent.** It has two entries: `LOADALL`, undocumented, 16/32-bit, and
   `SYSCALL`, `mode="e"` (long mode). Our first query took the first entry and reported a
   mnemonic mismatch. The claim "`0F 05` is `syscall`" is only true in 64-bit mode — which is
   what our ELF says, but the caveat belongs in the record rather than in someone's head.
2. **`83 /7` takes `I bs` — a *sign-extended* byte.** So `cmp r64, imm8` is only valid when the
   immediate fits in −128..127. `cmp rbx, 93` (`48 83 FB 5D`) is fine; an immediate of 200
   would be silently wrong and must use `81 /7` with `Iz`. The assembler does not yet check
   this — recorded as a wave-2b requirement, since adding `cmp` operands without the range
   check is exactly the "plausible wrong bytes" failure this standard exists to prevent.

## How to re-verify

The query is a 40-line Python read-only script over the XML: it walks `<one-byte>`/`<two-byte>`,
matches `value` and `<opcd_ext>`, prefers `mode="e"`, and compares the `<mnem>` to the expected
mnemonic. It was run as a one-off and is deliberately not committed: this project's build path
stays free of other languages, and the table above is the artefact that has to stay true.
